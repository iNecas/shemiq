# Implement `shemiq validate`
:::shemiq
type: task
parent: ./top-level.md
status: done
:::

## Context

The parent task defines the validation rules and two-task split. The current Cobra CLI puts command setup and the full `task new` handler in `cmd/root.go`; `internal/task/task.go` has project discovery that returns the nearest existing `.shemiq/`, or a fallback path when none exists. Validation can reuse this discovery but must check that the returned directory exists instead of creating one. There is no metadata parser yet. The sibling task, "Generate UUIDs for new tasks and adopt the metadata rules," will use the UUID generator provided here, update the skill and `task new`, and migrate existing documents; leave that task in place.

## Interview

- `--fix` inserts a missing UUID into a structurally parseable directive even if another field is invalid (such as `status: todo`); it then reports the remaining error. It must not silently repair any other field.
- Recognize a directive only when `:::shemiq` begins at column zero. Indented examples such as `    :::shemiq` are text; no Markdown fence-aware parser is needed.
- Return both repaired and unresolved findings as issues. A `Fixed` field marks only a finding actually repaired; print `path:line: fixed: message` for repaired findings and `path:line: message` for unresolved ones on stderr. Keep stdout empty and return nonzero only for unresolved issues.
- With no path, fail if no existing `.shemiq/` directory can be found upward from the working directory. Do not create one or scan the working directory as a fallback.
- Split the existing CLI implementation into `cmd/new.go` and `cmd/validate.go`, keeping root command setup in `cmd/root.go`; keep validation business logic in `internal/task`, not in a new validation package or in Cobra handlers.
- Have `internal/task` return structured validation issues (path, line, message, fixed flag) separately from operational errors. Mark the missing-UUID issue fixed only when the UUID was inserted; other issues in the same directive remain unresolved. Format findings in `cmd/validate.go`. When unresolved issues remain, print them once, suppress Cobra's duplicate error and usage output for that case, and return a non-nil error for the exit status; ordinary command failures can use Cobra's existing error handling.

## Implementation plan

- Extract the existing `task new` Cobra handler and title prompt from `cmd/root.go` into `cmd/new.go` without changing their behavior; leave root wiring and `Execute` in `cmd/root.go`. Add `cmd/validate.go` for the root-level `shemiq validate [path] [--fix]` command. Keep CLI argument handling and diagnostic printing in `cmd`, and put scanning, parsing, validation, repair, and project discovery behavior for validation in `internal/task` (separate Go files within that package as useful).
- With no path, call `task.FindProjectDirectory(cwd)` and check that the returned `.shemiq/` path currently exists as a directory. It already picks the nearest existing project when one exists; its absent-project fallback path must cause a clear error in validation, not directory creation. An explicit path selects one Markdown file or recursively selects Markdown files in a directory. Skip files without directives. Invalid paths or filesystem errors should fail clearly.
- Separate file selection from a small line-oriented parser and validation. An exact `:::shemiq` opens a block and `:::` closes it; a line beginning with `:::shemiq` but not matching the opener is malformed. Keep original file bytes and use private directive records holding block boundaries, a byte insertion offset, and parsed fields keyed by name with values and line numbers. Detect repeated keys while parsing rather than overwriting silently; keep malformed/unknown data reportable instead of requiring a typed, already-valid metadata struct. Report malformed fields or unterminated blocks; do not interpret indented examples as directives or enforce headings, filenames, or placement.
- Validate each directive independently: only `type`, `parent`, `source`, `status`, and `uuid` are known; reject repeated keys and empty values. Accept `top-level` or `task` for `type`, and `new`, `progress`, or `done` for `status`. Require a canonical lowercase UUIDv4 for every directive without `source`; reject a directive containing both `source` and `uuid`. Resolve `parent` relative to its document and require its target to be an existing file; do not require `source` targets to exist. Detect duplicate explicit UUIDs only among selected files, not unselected source documents.
- Expose a small `internal/task` entry point such as `Validate(cwd, path string, fix bool) ([]Issue, error)`, where an empty path means default discovery and `Issue` contains path, line, message, and fixed flag. Keep parser records, fields, and file-edit details private; split implementation into files within `internal/task` as useful rather than adding a public metadata model. `--fix` adds fresh UUIDs only to structurally parseable directives missing both `uuid` and `source`, inserting into the original bytes before the closing line without rejoining or reformatting other lines. Preserve the file's line-ending style and all unrelated text. Invalid field values do not block UUID insertion, but malformed blocks must not be rewritten speculatively. Never replace invalid or duplicate UUIDs or modify references. Revalidate the selected files after writing; a second fix run should be a no-op. Return an `Issue` for each repaired missing UUID with `Fixed: true`, together with remaining issues with `Fixed: false`, separately from filesystem/generation errors. `cmd/validate.go` prints each issue on stderr with its file and line, visibly distinguishing fixed findings. For unresolved issue-only failures, suppress Cobra's extra `Error:`/usage output while still returning a non-nil error. Clean checks and fully successful repairs succeed with empty stdout.
- Provide a small reusable UUIDv4 generator in `internal/task` using `crypto/rand` and returning `(string, error)` so the sibling `task new` work can call it without duplicating the implementation. The sibling task owns updates to `task new`, the skill, and existing `.shemiq/` documents; do not migrate them as part of this task.
- Exercise the command in temporary-project tests: default versus explicit file/directory scope and duplicate detection; `--fix` insertion and repeat-run stability; invalid metadata; missing parent versus allowed missing source; and failure when default discovery finds no project. Keep tests focused on end-to-end behavior rather than a broad parser matrix.

## Implementation notes

- Split CLI setup into `cmd/root.go`, `cmd/new.go`, and `cmd/validate.go`. The new command emits line-specific diagnostics to stderr and suppresses Cobra's duplicate error/usage output for validation findings; operational errors still use Cobra's normal reporting.
- Added scoped scanning, line-oriented directive parsing, field and reference checks, selected-file UUID uniqueness, and conservative byte-preserving `--fix` insertion in `internal/task`. Repairs are revalidated; only inserted UUIDs are reported as fixed. Added `task.NewUUID()` for reuse by the sibling task.
- Added focused command-level tests for selection and duplicates, successful and partial repairs, CRLF preservation and idempotence, invalid fields/references, and missing-project behavior. Moved the existing `task new` tests to `cmd/new_test.go`, with the shared CLI test helper in `cmd/command_test.go`. `go test ./...` passes.
- Left `task new`, the skill, and existing `.shemiq/` metadata unchanged for the sibling adoption task.
